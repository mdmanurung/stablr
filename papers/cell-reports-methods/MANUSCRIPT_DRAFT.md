# stablr: stability-based biomarker discovery with reproducible FDP+ control in R

Mikael Manurung

## Summary

High-dimensional omic studies often require biomarker signatures that are both
sparse enough to interpret and stable enough to trust across resampled cohorts.
STABL addresses this problem by combining bootstrap stability selection with
false discovery proportion control through artificial features, but the
reference implementation is Python-based. We developed `stablr`, a pure-R
implementation that exposes STABL-style fitting, FDP+ thresholding, artificial
feature generation, multi-omic integration workflows, and publication-oriented
diagnostics through R-native APIs. The package supports glmnet-family learners,
random-permutation and knockoff artificial features, grouped bootstrapping,
single-omic and multi-omic workflows, and optional cooperative fusion. We
validate the implementation against the pinned Python STABL reference on fixed
synthetic fixtures, where selection masks, FDP+ curves, stacking behaviour,
metric scalars and signal-feature ranking all agree. We also report a
full-profile run on the Onset of Labor proteomics tutorial dataset as a negative
result: it recovered all seven reference selected features but failed its frozen
acceptance thresholds, because the artificial-feature generator it used was
calibrated against a different null distribution than the Python reference. A
corrected run is pending, and we therefore make no OOL parity claim.
`stablr` makes stability-based biomarker discovery with
FDP+ thresholding available to R-centered omics workflows without requiring a
Python runtime.

## Introduction

Biomarker discovery from modern omic data is a high-dimensional feature
selection problem in which the scientific endpoint is often a short and
reproducible marker set, not only a predictive model. Sparse penalized models
can produce compact signatures, but selected features may vary across
resampling, preprocessing, and regularization choices. Stability selection
addresses this problem by repeatedly fitting sparse models on resampled data and
ranking features by recurrence. STABL adds false discovery proportion control by
contrasting real features with artificial null features, providing a practical
framework for sparse and reliable omic biomarker discovery.

The original STABL work established the method and released a Python reference
implementation. Many biomedical groups, however, conduct statistical modeling,
Bioconductor workflows, manuscript figures, and reproducibility checks in R.
Bridging STABL into this ecosystem requires more than a direct syntax port: the
implementation needs R-native data validation, S3 objects, `glmnet`-ecosystem
learners, documentation, package checks, and stable workflows for multi-omic
datasets.

We developed `stablr` to provide this R-centered software layer. The package
implements STABL-style bootstrap fitting, artificial-feature FDP+ calibration,
single-omic and multi-omic workflows, visualization helpers, and export
utilities. The current release is framed as software infrastructure and
cross-language validation, not as a new statistical method. We validate parity
on the Onset of Labor (OOL) proteomics tutorial data and provide release
artifacts, source code, documentation, and reproducibility files for inspection.

## Results

### An R-native implementation of STABL-style biomarker selection

The core `stablr` entry point is `stabl_fit()`. It accepts a feature matrix,
outcome vector, regularization grid, model family, artificial-feature strategy,
bootstrap settings, and random seed. Inputs are aligned by sample identifiers to
avoid position-based sample mismatches. The fitted object stores real-feature
scores, artificial-feature scores, FDP+ thresholds, selected features, learner
metadata, and reproducibility diagnostics. Public accessors include
`get_feature_names_out()`, `get_support()`, `get_stabl_scores()`,
`get_importances()`, and `transform_stabl()`.

The package supports lasso, elastic net, adaptive lasso, and optional sparse
group lasso learners, with gaussian, binomial, multinomial, and Cox outcomes
where the backend supports the family. Artificial features can be generated by
random permutation or knockoff-based strategies. Classic and group-aware
bootstrap helpers support ordinary resampling and blocked designs. Plotting
functions expose stability paths, FDP+ curves, ROC/PR curves, boxplots, and
feature scatterplots, while export helpers write selected features and scores to
disk.

### Multi-omic workflows are exposed through documented package APIs

`stablr` provides higher-level wrappers for multi-omic studies in which each
view is represented as a named feature matrix. `stabl_multiomic_train_validate()`
fits per-omic models and optional early, late, and cooperative fusion branches.
`stabl_multiomic_cv()` provides outer cross-validation when a fixed validation
split is not available, and `stabl_multiomic_nested_cv()` supports nested
evaluation infrastructure for heavier benchmark studies. Cooperative-fusion
diagnostics can be inspected through `get_cooperative_features()` and
`get_cooperative_diagnostics()`.

The release intentionally separates validated package functionality from
deferred benchmark claims. The TCGA nested-CV vs DIABLO scaffold is included as
research infrastructure, but no superiority claim is made without a completed
paired outer-fold benchmark and uncertainty intervals.

### OOL parity validation recovers the Python tutorial selected features

We evaluated `stablr` on the OOL proteomics tutorial dataset using
publication-scale settings: 150 samples, 1,317 protein features, gaussian lasso
models, 500 bootstraps, 10 lambda values, and a fixed seed. The analysis used the
same reference tutorial selected-feature set used in the Python workflow.

This evaluation is reported as a **negative result that is still under
adjudication, not as a validated parity claim**. A sealed full-profile run
(`stablr-0.1.1-c59780093899`, retained under
`RESULT_STATUS=not_ready`) selected nine features and recovered all seven Python
tutorial selected features, giving a selected-set Jaccard similarity of 0.778
and a maximum-stability-score Spearman correlation of 0.785. However, that run
requested a fixed-X knockoff construction that is infeasible when the number of
features exceeds the number of samples, so it silently fell back to
random-permutation artificial features. Its FDP+ was therefore calibrated
against a different null distribution than the Python reference, and the run
failed its own frozen acceptance thresholds (Jaccard >= 0.80, Spearman >= 0.90,
FDP-threshold delta <= 0.05; observed 0.778, 0.785, 0.08).

A corrected run using the Gaussian model-X equicorrelated knockoff construction
that the Python reference actually implements has not yet been executed at full
profile. A two-bootstrap smoke of that corrected pipeline was mechanically
successful in reaching the correct generator with no fallback, but two
bootstraps quantise the stability scores to three levels and make the resulting
Jaccard, Spearman and threshold figures uninterpretable; that smoke is retained
as non-promotable and is not reported here as a measurement.

We therefore make no OOL parity claim in this manuscript. The parity evidence
that is currently supported is narrower and is described in the cross-language
validation section: deterministic agreement of selection masks, FDP+ curves,
stacking behaviour, metric scalars, and signal-feature ranking against the
pinned Python STABL reference on fixed synthetic fixtures. Establishing OOL
parity requires a full-profile run with the corrected generator together with a
Monte-Carlo estimate of the correlation ceiling implied by the two implementations
drawing bootstrap resamples from independent random number generators.

### Release engineering supports reproducible use and review

The v0.1.0 release is distributed at
`https://github.com/mdmanurung/stablr/releases/tag/v0.1.0`, with documentation
at `https://mdmanurung.github.io/stablr/`. Local verification under R 4.5.1
completed with zero test failures (`FAIL 0 | WARN 0 | SKIP 1 | PASS 1611`) and
`R CMD check --no-manual --ignore-vignettes --no-build-vignettes` returned
`Status: OK`. All six source vignettes rendered to HTML, and the pkgdown site
was built and deployed. The one skipped local test requires a large external
`Sample Data/data.zip` fixture that is not bundled in the package checkout.

## Discussion

`stablr` makes STABL-style biomarker selection available to R users through a
tested package interface, while preserving the conceptual separation between the
original method and this R implementation. The package is most useful for
R-centered omics projects that need sparse selected-feature sets, FDP+
calibration, reproducible bootstrapping, and manuscript-ready diagnostics.

The parity validation is intentionally framed at the feature selection and
ranking level rather than as bit-identical coefficient reproduction. R `glmnet`
and Python scikit-learn-style elastic-net implementations differ in coordinate
descent schedules, convergence conventions, and numerical details. Therefore,
the appropriate validation target for this release is concordance of selected
features, stability score rankings, and FDP+ threshold behavior under matched
preprocessing and fixed seeds.

Several limitations remain. First, the present validation uses the OOL
proteomics tutorial dataset rather than a full reproduction of all original
STABL clinical benchmarks. Second, TCGA nested-CV vs DIABLO is implemented as
infrastructure but deferred as a performance benchmark because a previous full
job timed out and did not produce a complete cache. Third, cooperative fusion is
provided as an R workflow extension and should not be interpreted as part of the
original STABL method unless separately benchmarked. These boundaries are
documented to keep claims aligned with available evidence.
